## 1. システム概要

### 1.1 システム名

MindLog

### 1.2 概要

自分の日々の出来事、反省点、学び、気付き、悩みなどを記録・整理し、言語化するためのWebアプリケーション。

単純な日記アプリではなく、記録する目的に応じて複数の「モード」を選択できる点が特徴。

### 1.3 開発目的

- アプリの完成そのものよりも、実務に近い開発工程（要件定義→基本設計→詳細設計→DB設計→環境構築→実装→テスト）を経験することを重視する。
- ソースコード・設計書等はGitHubで管理する。

## 5. 機能要件 (FR)

### 5.1 認証・ユーザー管理

| ID | 要件名 | 内容 |
|---|---|---|
| FR-001 | ログイン機能 | メールアドレスとパスワードでログインする。メールアドレスをユーザーIDとして扱う。 |
| FR-002 | 新規ユーザー登録機能 | ユーザー自身がメールアドレス／パスワード／パスワード（確認）を入力して登録できる。パスワードとパスワード（確認）は一致している必要がある。メールアドレスの重複は許可しない。パスワードは最低8文字以上、かつ英数字を混在させる必要がある（入力ルール違反時はFR-004参照）。登録成功後はログイン画面へ遷移し、登録完了のメッセージを表示する。 |
| FR-003 | ログイン失敗時の表示 | ログイン失敗時はログイン画面を再表示し、「メールアドレスまたはパスワードが正しくありません。」等のエラーメッセージを表示する。メールアドレスの存在有無とパスワードの正誤は個別に通知しない（[6.1 NFR-002](#61-セキュリティ)参照）。 |
| FR-004 | 新規登録時のエラー表示 | 入力内容に問題がある場合、登録画面を再表示しエラーメッセージを表示する。想定エラー：メールアドレス形式不正、メールアドレス重複、パスワード不一致、パスワードの入力ルール違反。メールアドレス形式チェックは、`@`と`.`を含むか等の一般的な標準形式バリデーションとする（厳密なルールは設けない）。 |
| FR-005 | ログアウト機能 | ログアウトできる。ログアウト後は認証が必要な画面へアクセスできない。 |

### 5.2 記録モード（入力）

| ID | 要件名 | 内容 |
|---|---|---|
| FR-006 | 問題解決モードでの記録作成 | 入力項目：タイトル、目標、現状、ギャップ、原因、対策。困っていること・悩んでいることを整理し解決策を考えるためのモード。 |
| FR-007 | 日記モードでの記録作成 | 入力項目：タイトル、メモ。形式を決めず自由に記録するモード（用途は限定しない）。 |
| FR-008 | 1日の振り返りモードでの記録作成 | 入力項目：タイトル、今日の出来事、反省点、学び、気付き、明日やること。その日の行動を振り返り自己フィードバックを行うモード。 |
| FR-009 | モード選択機能 | 記録作成時に「問題解決」「日記」「1日の振り返り」のいずれかのモードを選択し、選択したモード専用の入力フォームを表示する。 |

### 5.3 記録の基本操作

| ID | 要件名 | 内容 |
|---|---|---|
| FR-010 | 記録の複数作成 | 1日に何件でも記録を作成できる。 |
| FR-011 | 対象日の管理 | すべての記録に「対象日」を持たせる。対象日は記録の作成日時とは別に管理する。新規作成時は現在の日付を初期値とし、ユーザーは変更できる。 |
| FR-012 | 作成日時の記録 | 記録を作成した日時を保持する。 |
| FR-013 | 更新日時の記録 | 記録を最後に編集した日時を保持する。 |
| FR-014 | 記録編集機能 | 保存済みの記録を編集できる。編集画面には対象記録の現在の値を初期表示する。保存後はその記録の詳細画面へ遷移する。 |
| FR-015 | 記録削除機能 | 保存済みの記録を削除できる。削除ボタン押下時は確認ダイアログ（「この記録を削除しますか？」／キャンセル・削除）を表示する。キャンセル時は詳細画面へ戻り、削除実行時は記録一覧へ遷移する。 |

### 5.4 ダッシュボード

| ID | 要件名 | 内容 |
|---|---|---|
| FR-016 | ダッシュボード表示 | ログイン成功後に表示する。「新しく記録する」「最近の記録」「すべての記録を見る」「ログアウト」等を配置する。 |
| FR-017 | 最近の記録表示 | ダッシュボードに最近の記録を表示する。件数は**最新5件**。並び順は更新日時の新しい順。 |

### 5.5 記録一覧・詳細

| ID | 要件名 | 内容 |
|---|---|---|
| FR-018 | 記録一覧表示 | 対象日・タイトル・モード・作成日時・更新日時の5項目をすべて表示する。並び順は更新日時の新しい順。 |
| FR-019 | 記録詳細表示 | 対象日・タイトル・モード・モード固有の入力内容・作成日時・更新日時を表示する。編集・削除ボタンを配置する。 |

### 5.6 検索

| ID | 要件名 | 内容 |
|---|---|---|
| FR-020 | 記録検索機能 | 記録一覧から、モード／対象日／タイトルキーワードを条件に検索できる。ユーザーが指定した条件のみを検索条件として使用し、未指定の条件は検索条件に含めない。複数の条件を指定した場合はAND条件（すべての条件を満たす記録のみ表示）とする。 |
| FR-021 | モードによる検索 | 「問題解決」「日記」「1日の振り返り」から選択して検索できる。未指定の場合はモードを検索条件に含めない。 |
| FR-022 | 対象日による期間検索 | 開始日・終了日を指定して検索する。両方入力されている場合のみ有効。開始日のみ、終了日のみの指定は不可。 |
| FR-023 | 日付入力エラー処理 | 開始日が終了日より後の場合は検索を実行せず、「開始日は終了日以前の日付を指定してください。」等のエラーメッセージを表示する。 |
| FR-024 | タイトルキーワード検索 | タイトルを対象に部分一致で検索する。本文（モード固有の入力内容）は検索対象としない。 |
| FR-025 | 検索結果0件時の表示 | 検索条件に一致する記録が存在しない場合、「該当する記録がありません。」と表示する。 |

### 5.7 ユーザーとデータ管理

| ID | 要件名 | 内容 |
|---|---|---|
| FR-026 | ユーザーと記録の紐付け | 記録は必ずユーザーに紐付ける（ユーザー1に対し記録N の関係）。 |
| FR-027 | データアクセス制御 | ユーザーは自身が作成した記録のみ閲覧・作成・編集・削除できる。他ユーザーの記録は閲覧・編集・削除できない。この制御は画面上だけでなくサーバー側でも実施し、URLの record ID を直接変更する等の操作でも他ユーザーの記録にアクセスできないようにする。 |

## 7. 入力項目の必須／任意ルール

- 現時点では、記録の各入力項目に必須条件を設けない。**すべて任意入力**とし、入力項目が空欄でも記録を保存できる。
- ただし、認証に関わる項目（メールアドレス・パスワード）は別途入力ルールを設ける。パスワードは**最低8文字以上、かつ英数字混在必須**（FR-002）。
- タイトルが未入力（空欄）の記録は、一覧・検索結果・ダッシュボードにおいて「（無題）」という固定文言で表示する（FR-018、FR-019、FR-017）。

### モード別入力項目一覧

| モード | 入力項目 |
|---|---|
| 問題解決 | タイトル、目標、現状、ギャップ、原因、対策 |
| 日記 | タイトル、メモ |
| 1日の振り返り | タイトル、今日の出来事、反省点、学び、気付き、明日やること |

## 9. ユーザー操作フロー

### 9.1 ログイン

```
ログイン画面（メールアドレス／パスワード入力）
  → 成功：ダッシュボードへ
  → 失敗：ログイン画面を再表示＋エラーメッセージ（FR-003）
```

### 9.2 新規登録

```
新規登録画面（メールアドレス／パスワード／パスワード確認）
  → 成功：ログイン画面へ（登録完了メッセージを表示）
  → 失敗：新規登録画面を再表示＋エラーメッセージ（FR-004）
```

### 9.3 記録作成

```
ダッシュボード「新しく記録する」
  → モード選択画面（問題解決／日記／1日の振り返り）
  → 選択したモード専用の入力フォーム
  → 保存
  → 作成した記録の詳細画面
```

### 9.4 記録編集

```
記録詳細画面「編集」
  → 記録編集画面（現在値を初期表示）
  → 保存
  → 編集した記録の詳細画面
```

### 9.5 記録削除

```
記録詳細画面「削除」
  → 確認ダイアログ「この記録を削除しますか？」
    → キャンセル：詳細画面へ戻る
    → 削除：記録を削除し、記録一覧へ
```

### 9.6 検索

```
記録一覧画面（モード／対象日（期間）／タイトルキーワードを任意で指定）
  → 条件に一致する記録を一覧表示
  → 0件の場合：「該当する記録がありません。」
  → 開始日＞終了日の場合：検索を実行せずエラーメッセージ（FR-023）
```

## 10. モード間の関係

3つのモード（問題解決／日記／1日の振り返り）は独立した記録方式として扱う。

想定される使い方の例：「1日の振り返り」で問題を見つけ、「問題解決」モードで整理する、といった連携は利用者の運用として可能だが、**記録同士を直接紐付ける機能は現時点では実装しない**。あくまで「1つのアプリケーション内に複数のモードが存在し、それぞれを自由に使える」という考え方に基づく。

## 14. 要件間レビュー結果

本要件定義書作成にあたり、記載内容間の矛盾の有無を確認した。

- **「入力項目は原則すべて任意」（7節）と「タイトルは一覧表示・検索に使用する」（5.6, 8節）の関係**：矛盾ではないが、タイトルが空欄の記録が一覧・検索結果にどう表示されるかを確認し、「（無題）」固定文言表示に決定（7節）。
- **検索条件（モード／対象日／タイトル）を複数同時に指定した場合の結合方法**：AND条件に決定（FR-020）。
- 上記2点を除き、記載内容間に明確な矛盾は確認されなかった。
